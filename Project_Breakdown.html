4.1 Sentence-BERT (Dense Semantic Matching)

🧠 Model: all-MiniLM-L6-v2 Library: sentence-transformers (Hugging Face)  |  Output: 384-dimensional dense vector  |  File: app/services/embedding.py

What is Sentence-BERT?

Sentence-BERT (SBERT) is a modification of the BERT transformer model that produces semantically meaningful sentence-level embeddings. Unlike word-level models, SBERT understands the meaning of entire paragraphs.

How We Use It

  1. When a resume is uploaded, the extracted text from each section (summary, skills, experience, education) is passed through SBERT.
  2. SBERT converts each text chunk into a 384-dimensional floating-point vector (a list of 384 numbers).
  3. This vector captures the semantic meaning of the text — similar meanings produce similar vectors.
  4. The vectors are stored in PostgreSQL using the pgvector extension.
  5. The same process happens for the job description.
# app/services/embedding.py
from sentence_transformers import SentenceTransformer

model = SentenceTransformer('all-MiniLM-L6-v2')  # 384-dim output

def generate_embedding(text: str) -> list[float]:
    if not text:
        return [0.0] * 384  # zero vector for empty text
    return model.encode(text).tolist()

4.2 Cosine Similarity (Score Computation)

📐 Mathematical Formula Used to measure how "close" two vectors are in 384-dimensional space. A score of 1.0 = perfect match, 0.0 = no similarity.
similarity(A, B) = (A · B) / (‖A‖ × ‖B‖)

Where A is the resume embedding vector and B is the job description embedding vector. The dot product measures alignment, divided by the product of their magnitudes to normalize to a 0–1 scale.

# app/services/matcher.py
def cosine_similarity(v1, v2):
    a = np.array(v1)
    b = np.array(v2)
    dot = np.dot(a, b)           # dot product
    norm = np.linalg.norm(a) * np.linalg.norm(b)  # magnitudes
    if norm == 0:
        return 0.0
    return float(dot / norm)

4.3 Hybrid Weighted Score Formula

The final match score is a weighted combination of three sub-scores:

Final Score = (0.4 × Dense Score) + (0.4 × Skill Score) + (0.2 × Experience Score)
ComponentWeightHow It's Computed
Dense Score40%Average cosine similarity between SBERT embeddings of resume sections and job description
Skill Score40%Keyword overlap between extracted skills and job requirements
Experience Score20%Years of experience vs. job requirements match

4.4 spaCy NLP Pipeline

🏷️ Model: en_core_web_sm Library: spaCy 3.7  |  Task: Named Entity Recognition (NER)  |  File: app/services/pii_redactor.py

What spaCy Does in Our Project

spaCy is used specifically for PII (Personally Identifiable Information) redaction — removing personal data from resumes before storing them or sending them to the LLM:

NLP TechniqueWhat It DetectsReplacementMethod
Regex Pattern MatchingEmail addresses[EMAIL]Regular expression: [a-zA-Z0-9_.+-]+@...
Regex Pattern MatchingPhone numbers[PHONE]Regular expression: \(?\d{3}\)?[-.\s]?\d{3}...
Named Entity RecognitionPerson names[PERSON]spaCy PERSON entity label
Named Entity RecognitionLocations (cities, countries)[LOCATION]spaCy GPE and LOC entity labels
# app/services/pii_redactor.py — Two-phase PII redaction
import re, spacy

nlp = spacy.load("en_core_web_sm")

def redact(raw_text):
    # Phase 1: Regex (deterministic)
    text = re.sub(r'email_pattern', '[EMAIL]', raw_text)
    text = re.sub(r'phone_pattern', '[PHONE]', text)

    # Phase 2: spaCy NER (ML-based)
    doc = nlp(text)
    for ent in doc.ents:
        if ent.label_ == "PERSON":
            text = text.replace(ent.text, "[PERSON]")
    return text
ℹ️ About Lemmatization spaCy's en_core_web_sm model internally uses a lemmatizer as part of its NLP pipeline. Lemmatization converts words to their base form (e.g., "running" → "run", "better" → "good"). While we don't call the lemmatizer explicitly, it runs automatically inside spaCy's tokenization pipeline when performing NER. The Sentence-BERT model also uses its own WordPiece tokenizer which handles subword decomposition.

4.6 Google Gemini LLM (Skill Gap Analysis)

🤖 Model: gemini-1.5-flash Library: google-generativeai  |  Task: Structured skill gap analysis  |  File: app/services/llm_gateway.py

What Gemini Does

After match scores are computed, the system sends the redacted resume text and job description to Google's Gemini 1.5 Flash LLM with a carefully engineered prompt:

  1. Gemini acts as an expert technical recruiter and ATS system
  2. Identifies up to 3 missing skills or experiences
  3. For each gap, it returns:
    • skill_name — the missing skill
    • current_level — what the candidate currently has
    • required_level — what the job requires
    • severity — critical, moderate, or minor
    • recommendation — specific learning resources
  4. Output is enforced as strict JSON (validated by Pydantic)

Why gemini-1.5-flash?

  • Free tier: 60 requests/minute at no cost
  • Low latency: ~1-2 second response time (vs. 5-10s for larger models)
  • Structured output: Reliably generates valid JSON arrays
