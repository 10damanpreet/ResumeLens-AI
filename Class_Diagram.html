Class Diagram

ResumeLens AI — Intelligent Resume-Job Matching & Skill Gap Advisory System

Prepared by: Damanpreet Singh  |  Course: Software Engineering  |  Date: September 2026

1. Class Diagram

The following diagram represents the core domain model classes, service classes, and their relationships in the ResumeLens AI system. The system follows a layered architecture pattern with Models, Services, and API layers.

Candidate
- id: UUID (PK)
- email: String (unique)
- password_hash: String
- role: Enum (candidate|admin)
- created_at: DateTime
+ verify_password(plain: str): bool
+ set_password(plain: str): void
Resume
- id: UUID (PK)
- candidate_id: UUID (FK)
- filename: String
- raw_text: Text
- skills_json: JSON
- embedding: Vector(384)
- uploaded_at: DateTime
+ get_skills(): List[str]
JobDescription
- id: UUID (PK)
- candidate_id: UUID (FK)
- title: String
- description_text: Text
- embedding: Vector(384)
- created_at: DateTime
+ get_requirements(): List[str]
MatchEvaluation
- id: UUID (PK)
- resume_id: UUID (FK)
- job_id: UUID (FK)
- dense_score: Float
- sparse_score: Float
- hybrid_score: Float
- created_at: DateTime
+ compute_hybrid(): Float
SkillGap
- id: UUID (PK)
- evaluation_id: UUID (FK)
- skill_name: String
- current_level: String
- required_level: String
- severity: Enum (high|med|low)
- recommendation: Text
+ to_dict(): Dict
AtsReport
- id: UUID (PK)
- evaluation_id: UUID (FK)
- formatting_score: Float
- keyword_density: Float
- suggestions: JSON
+ to_dict(): Dict

2. Service Classes

MatcherService
- model: SentenceTransformer
+ cosine_similarity(v1, v2): float
+ dense_match(resume, job): float
+ sparse_match(resume, job): float
+ hybrid_score(dense, sparse): float
EmbeddingService
- model_name: String
- dimension: int = 384
+ generate_embedding(text): List[float]
LLMGateway
- api_key: String
- model: String = "gemini-pro"
+ generate_skill_gap_feedback(
    resume_text, job_text): List[Dict]
ResumeParser
- nlp: spacy.Language
+ extract_text(pdf_path): str
+ extract_skills(text): List[str]
+ segment(text): Dict[str, str]
+ redact_pii(text): str
CeleryWorker
- broker_url: String (Redis)
- timezone: String = "UTC"
+ run_evaluation_pipeline(
    resume_id, job_id): UUID
Settings
+ DATABASE_URL: String
+ REDIS_URL: String
+ JWT_SECRET_KEY: String
+ GEMINI_API_KEY: String
+ APP_NAME: String
+ get_settings(): Settings

3. Class Relationships

RelationshipTypeCardinalityDescription
Candidate → ResumeComposition (has)1 : 0..*A candidate can upload zero or more resumes.
Candidate → JobDescriptionComposition (has)1 : 0..*A candidate can create zero or more job descriptions.
Resume → MatchEvaluationAssociation1 : 0..*A resume can be evaluated against multiple jobs.
JobDescription → MatchEvaluationAssociation1 : 0..*A job description can be matched with multiple resumes.
MatchEvaluation → SkillGapComposition (has)1 : 0..*Each evaluation produces zero or more skill gaps.
MatchEvaluation → AtsReportComposition (has)1 : 0..1Each evaluation may produce one ATS compatibility report.
MatcherService → EmbeddingServiceDependency (uses)—Matcher uses the embedding service for vector generation.
CeleryWorker → MatcherServiceDependency (uses)—Worker invokes the matcher for score computation.
CeleryWorker → LLMGatewayDependency (uses)—Worker invokes the LLM for skill gap analysis.
